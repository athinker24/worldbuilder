# Renderer

Guidance for `src/renderer`. Two pointers before anything else:

- **Before editing `MapView.tsx`, `pixiLabels.ts`, `pixiShapes.ts`, `ToolPanel.tsx`, `Timeline.tsx`
  or `HierarchyPanel.tsx`, read [`docs/map-internals.md`](../../docs/map-internals.md).** It
  carries the rendering split, the measured performance findings and the list of fixes that were
  tried and reverted.
- Markdown, asset names and anything read out of a `.world` are untrusted — the rules are in
  [`docs/security-gates.md`](../../docs/security-gates.md).

**Undo/redo (`src/renderer/src/undo.ts`):** double stack (`undoStack`/`redoStack`); every mutation is recorded as an `{undo, redo}` pair. A deleted-then-restored row gets a new database id, so identity is kept in sync across closures via a mutable `{id}` ref object (see the `pm:create`/`pm:remove` handlers in `MapView.tsx`). Extend undo/redo without breaking this pattern. A failing step pushes the entry back on its stack and returns false — it must never corrupt the stacks. **Every entry also carries a `label` (+ optional `params`), and the ENGLISH TEXT IS THE KEY** — `History.tsx` translates at render, so a list read after switching languages is not half Turkish; a drawing's kind is part of the key rather than a parameter, or the raw English word lands inside a Turkish sentence. `undo.ts` is a **store**: `subscribeHistory` + a cached snapshot for `useSyncExternalStore` (rebuilt only on a real change — returning a fresh object per call re-renders forever). `goTo(n)` walks ONE STEP AT A TIME: every entry's closures assume the state the step before it left, and identity drift means out-of-order replay mends the wrong row; it stops at the first failure, where `run` has already put the entry back. **The History panel lives in the map toolbar** beside Layers and Boards — most of what it lists are drawings, so leaving the map to step back through them is the one thing it must not require. It scrolls itself to the current step and dims (never strikes through) the undone ones: they are not deleted, they are what continuing from here would cost.

**Renderer containment (Leaflet stays inside `MapView.tsx`) — a standing rule:** no other file may `import` leaflet/geoman or name a Leaflet type. Geometry crosses module boundaries as GeoJSON **strings**; shared geometry math lives as pure functions in `api.ts` (`ringArea`, `inYearRange`, …). This holds today (`L.` appears in exactly one file) and must keep holding. The reason is that this is NOT a web map: `CRS.Simple` is Leaflet's "not really a map" mode — no tiles, no projection, the default wheel zoom is replaced by our own rAF loop, and the whole of `updateOverlaySizes` exists to UNDO Leaflet's screen-fixed overlay design (we want everything to scale with the world). So the app is deliberately built on a library whose grain it runs against. **The containment is what made the eventual move cheap, and it now covers the two WebGL modules too — neither `pixiLabels.ts` nor `pixiShapes.ts` imports Leaflet.** They take plain numbers; MapView owns the translation. Counterweight to keep in mind: WebGL content is absent from the DOM (no screen reader, no text selection, no keyboard focus), so optimisation and accessibility pull in opposite directions here.

**A stroke's UNIT is part of the rendering split, and the two sides must not drift:** a POLYGON's outline is screen pixels (a border is a pen stroke saying where one thing stops, drawn at a constant width whatever the scale, as on paper) and a PATH's is map pixels (a road has a real width on the ground and belongs to the terrain). Leaflet does it with the patched `L.SVG._updateStyle` writing `--w` plus the pane's `--mz`, polygons opting out with `--mz: 1`; pixiShapes does it by dividing a closed shape's width by the scale and letting an open one ride the container. The rule was written for Leaflet and NOT carried across when shapes moved to WebGL, so for a while it applied to exactly one drawing at a time — the selected one, the only one Leaflet still holds — and selecting a road made it jump from 3 screen px to 3 map px and back. Dash patterns follow the width, since `lineDashArray` derives them from the weight. A path's thickness readout deliberately does not say "px"; a polygon's does. 

**Atlas (`Atlas.tsx`):** a read-only statistics page, the Overview workspace's first tab — per-map base-polygon areas in the chosen year (`ringArea` × `mapScales.perUnit²`), colored bars + percentages per state (that year's chain top) and per map-mode dimension. No new data/IPC; computation in `useMemo`, data fetched once on mount. Color sources are shared with the map (`fields.color`/`modes.colors`/`autoColor`). **Shared helpers (`api.ts`, single source with MapView — a rule change updates both):** `ringArea` (shoelace), `lowestRungSet` (base set), `rootAtYear` (year-based chain top, fed via a `parentsOf` callback from MapView refs / Atlas raw fields), `inYearRange`.

**Entity templates (`api.ts` + `ProjectPreferences.tsx` + `EntityPage.tsx`):** `templates` in `settings` = `EntityTemplate[]` (`{name, type?, fields}` — field name + default value; no schema change). Edited in tabs in Project Preferences (the `activeGov` pattern from Hierarchy Ranks), snapshotted from an entity page via "Save as template". **Applying only ADDS missing fields, never overwrites; the type is assigned only when the entity is untyped** — a starting point, not an imposition; goes through `saveFields` → undo for free. Fields that must not enter templates live in the `RESERVED_FIELDS` constant (the union of db.ts's TECH set + EntityPage's render filter + person fields); map-mode dimensions are filtered at runtime by the caller.

**The entity page (`EntityPage.tsx`):** a banner on top (`fields['banner']` = assets/-relative path, via `pickImage`; horizontal band, `object-fit: cover`; dashed placeholder without one). Below the content, a **tabbed notes region**: the `fields['notes']` JSON (`{title, content, collapsed}[]`), right-click → new tab, each note a vertical accordion block (markdown + wiki links, height via `resize: vertical`, ✏️/📖 edit toggle). The bottom section has three tabs: **[Hierarchy]** (tags, government, parent, dimensions, map history) / **[Dynasty]** / **[Links]** — the `<datalist id="entity-list">` sits OUTSIDE the tab conditions (all tabs' forms use it). All field writes go through `saveFields` → `save()`, undo for free.

**The dynasty system:** ruler history is `fields['ruler']` = `[{from, id}]` (same pattern as the parent chain; `getYearRecs(fieldsJson, key)` in `api.ts` is the general reader, `getParents` its 'parent' specialisation). Family ties live in the existing `links` table under the `'mother'/'father'/'spouse'` relation names (schema/state constants); the spouse link reads both ways, children derive from inLinks. Typing a name creates the entity on the spot via `findOrCreate` when missing. **`FamilyTree.tsx`**: the tree is not separate data — derived from links: climb the ancestor chain from the centred person, descend the whole line from the founder as nested ul/li with classic CSS connectors; click a person → the tree recenters, 📖 → their page. Data comes via `api.listLinks()` (the one method added to main) + `listEntities`; in inter-dynasty marriages a person appears once (`seen`), a couple-based layout can come later if needed.

**Per-map settings, and where the line is (`perMapRaw`/`perMapEntry`/`savePerMap` in `api.ts`):** five keys are one `{[mapId]: value}` row rather than a row per map — `mapScales`, `mapBoards`, `mapYears`, `travelModes`, `mapLayers` (plus `hideMapHint`, which is a LIST of ids and so is handled beside the loop rather than bent into it). **The rule for which side a setting falls on: anything measured in a map's own terms belongs to that map, because the ruler itself does.** The scale is per map, so a speed in units/day cannot be project-wide; the year you are reading at is a position, not a fact about the world; the layer toggles are about kinds this map actually has (a city plan has no realm polygons to hide, and those toggles used to follow you back to the continent). **Deliberately NOT per map, so nobody "fixes" them later:** entities, links, parent chains and ruler histories (world data — a county belongs to its duchy whichever map draws it, which is exactly what lets a rank chain resolve across maps), the rank ladders and government forms (project structure; "this map needs different ranks" is answered by a government form, not by a per-map ladder), `mapModes` dimensions and colours (a religion is the same colour everywhere), the calendar itself, and the library/preference keys (`entityFolders`, `favorites`, `templates`, `pinImages`, `recentColors`, `drawSettings`). **Deleting a map takes its per-map entries with it and undo puts them back** (`takeMapSettings`/`restoreMapSettings`, called from `deleteMapWithUndo` AFTER the delete so a refused delete cannot strip a map that is still there). That is not tidiness: `maps.id` is a plain rowid with no `AUTOINCREMENT` and **SQLite hands it back**, so deleting the newest map and creating one gave the new map the dead one's scale, boards and year — a map you never calibrated, already calibrated, in a unit you did not choose. A key added to the list above and not to `PER_MAP_KEYS` re-opens that silently.

**Auto-save + toast (`App.tsx`):** when a `.world` IS open and dirty, a silent `api.saveWorld()` every 3 minutes (NO timer in main — the renderer polls via `worldInfo()`, no new IPC channel). With no file, nothing happens (no save dialog stealing focus; an unsaved session is packed into `backups/` on close anyway). Ctrl+S and auto-save report through the same `showToast` channel (`.toast`, 2.2s, not modal).

**`[[` entity-name completion (`EntityPage.tsx`):** in both the main content and note-tab textareas. The boxes are deliberately UNCONTROLLED (defaultValue + save on blur) → the insertion writes straight into the DOM (the `sugEl` ref; the element CANNOT live in state — the `el.value` write reads as "state mutation after render" to react-hooks/immutability). **`onMouseDown` preventDefault on the suggestion buttons is REQUIRED**: if the click blurred the textarea, onBlur would save the old text, remount, and lose the insertion. Query = the nearest `[[` behind the caret (no suggestion when `]]` or a newline intervenes). The box anchors below the TEXTAREA, not the caret (caret-to-pixels would need a mirror div).

**Preset + recent colors (`ColorPicker.tsx` + `api.ts`):** six fixed presets above every picker (`PRESETS` — crimson/blue/green/gold/purple/turquoise; fixed hex, NOT tokens — map content is exempt from theming; the drawing defaults #c0603a and #7bb3ff are deliberately in the set), below them `settings.recentColors` (newest first, 12 entries; `getRecentColors`/`pushRecentColor`, module-level cached — pages hold many pickers). Recording happens on popup CLOSE: dragging emits every frame and intermediate colors would fill the strip with noise.

**Shortcut help (`Shortcuts.tsx`):** a read-only page opened from Help ▸ Keyboard Shortcuts and F1; shortcuts live in a single `GROUPS` array. New shortcuts must add a row here too.

**Theme (`main.css` + `App.tsx`):** three themes — dark (neutral grey, default) / light (turquoise) / **Dark Teal** (`[data-theme='teal']`, the tinted dark theme this app had before the greys, kept as a choice). **A theme IS a `data-theme` value plus the tokens it disagrees with, and nothing else** — Dark Teal overrides eight; that is what would make a user-defined theme an addition rather than a rewrite. An unknown value in `prefs.json` falls back in `getTheme` rather than reaching the DOM. **The dark chrome is grey on purpose and the accent is not for surfaces:** the surfaces used to carry a teal tint and across a whole screen that read as a coloured UI rather than a dark one, so colour is now reserved for meaning (links, focus, the active thing, the one primary button). The grey ramp was DERIVED, not picked — each value is the neutral grey with the same measured L\* as the tinted colour it replaced, green lifted one 8-bit step; only hue was removed, which is why the ramp still ascends and every contrast ratio held without re-tuning. Keep that rule if they are touched again. All colors come from the token layer at the top of `main.css`: `:root` holds dark values, `[data-theme='light']` the light overrides. Surfaces are named by ROLE (`--surface-canvas/sunken/base/raised/float`, `--control`), alongside `--text`/`--text-muted`/`--text-faint`, `--accent`/`--accent-soft`/`--accent-ink`, `--border-subtle`/`--border-strong`, `--danger`/`--danger-contrast`, `--gold`, `--male`/`--female`, `--overlay`, `--tint-*`, `--shadow-1..3`, and the scales `--sp-1..6` / `--fs-0..7` / `--r-s,m,l` / `--h-sm,md,lg` / `--dur`,`--dur-fast`. The old `--bg0..--bg3`/`--muted`/`--border` aliases are GONE — they were a bridge while the surfaces were renamed, and two names for one value is what a token layer exists to remove. **A literal left in the stylesheet is now an exception on purpose:** every declaration whose value already matched a scale step names it, all-or-nothing per declaration (half-tokenising `padding: 4px 10px` would bury the off-ramp 10 inside a line that looks migrated), so `grep 'font-size: [0-9]'` returns the real exceptions and nothing else. The choice lives in the `theme` key of `settings` (`getTheme/saveTheme` in `api.ts`, a copy of the language pattern); `App.tsx` writes `document.documentElement.dataset.theme` — switching is live, no reload. New UI colors must use tokens, NOT fixed hex. **Deliberately theme-exempt:** map content (drawing defaults, autoColor, poly-label/scale-bar white+shadow, pin badge frame) and the color picker's absolute color space (`.cp-sv`/`.cp-hue`) — fixed in both themes.

**Sidebar grouping by map (`Sidebar.tsx` + `db.entityPlacements`):** the whole entity tree — search, the folder tree, the map/board grouping, favourites and the workspace nav — is `Sidebar.tsx`, split out of App. **The line was drawn at WHERE THE DATA LIVES, not at the component tree:** everything App fetches in one `refresh()` (`entities`, `maps`, `folders`, `placements`) stays App's and arrives as a prop, and everything only this panel cares about (`collapsed`, `renamingFolder`, `sortKey`, `openGroups`, `closedBoards`, `favorites`, `boards`, `dragItem`) lives inside. Three things that look like they belong there and do not: `selected`/`selectedFolders` (the Del shortcut deletes them from anywhere), `search` (an argument to `api.listEntities`, so the fetch owns it) and `folders` (the entity page, the map and the palette all colour by folder). **Multi-select is TWO sets because the two kinds of row have two kinds of id**, and ticking a folder cascades into both — its subfolders into `selectedFolders`, its entries into `selected`, at any depth (`toggleFolderSel`; `folderPartial` is the indeterminate third state). That is not decoration: the bulk delete removes what is ticked, so a folder's tick has to name its contents or the dialog would announce a number the checkboxes never agreed to. **The bulk delete and the context menu's folder delete are deliberately different actions** — the bulk one deletes the contents, the context-menu one promotes them to the parent and its label says `(entries are kept)`. **Entry deletion is undoable and folder deletion is not** (folders are organisation, written optimistically to `settings`), so Ctrl+Z after a bulk delete brings the entries back at the root and not the folders; the confirm says so rather than leaving it to be discovered. `View` moved to `views.ts` for the same reason — App imports Sidebar, so a type exported from App would be a cycle. Once a map is open, the entity tree groups into accordions — the open map expanded, other maps collapsed under their names, and everything with no drawing anywhere in a `Not on a map` group at the bottom. Membership is **derived from drawings** (`entityPlacements` = `{entity_id, map_id, board}` straight off `features`), never stored on the entity: an article joins a map by being drawn there and leaves when the drawing goes. An article on two maps appears under both. The folder tree renders inside every group filtered to it (`allow: Set<number>` threaded through `renderChildren`/`renderFolderRow`; `folderShown` skips folders with nothing inside). **Boards are the inner tier and default the OPPOSITE way** — a map group is somewhere you are not (closed unless in `openGroups`), a board is a layer of the map you are on (open unless in `closedBoards`); that asymmetry is the whole distinction between the two. Search flattens the tree as before (grouping would hide hits); `addEntity` force-opens the unplaced group since new articles land there. **Favourites are a group above all of them** — a hover-revealed star per row (the `.sel-box` pattern: hidden until hover, but a star that is ON stays lit, because at that point it is the row saying what it is), the list in `settings.favorites` as ids and deliberately NOT a field on the entity (which entries you keep to hand is how you work in this world, not a property of the entry; in `fields` it would surface in templates, the notes export and the entry page). The group is FLAT and open by default — a handful of hand-picked entries put back behind two levels of folder would be the walk they were starred to avoid — and an id whose entry is gone is skipped when the group is built (the orphan-id rule boards already use), so deleting never has to reach in.
