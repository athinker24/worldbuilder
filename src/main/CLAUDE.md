# Main process

Guidance for `src/main`. The security gates that govern this side are in
[`docs/security-gates.md`](../../docs/security-gates.md) — read them before touching `db.ts`,
`index.ts`, `unpackWorld`, `packWorld`, the CSP or the IPC write boundary.

**Legacy-key migration:** the codebase was Turkish once and its persisted keys were too. `migrateLegacyKeys()` (db.ts) renames them in place on every launch and after every `.world` unpack (üst→parent, sancak→banner, notlar→notes, hiyerarşi→hierarchy, yönetim→government, yönetici→ruler, hane→house, renk→color, cinsiyet→gender, doğum→birth, ölüm→death; links.relation anne/baba/eş→mother/father/spouse; gender values erkek/kadın→male/female). Idempotent; never overwrites an existing English key; leaves user-defined map-mode dimensions (din, dil…) untouched — those are the user's vocabulary. Asserted in the db self-check with a legacy world.

**Data location + the .world document model:** the working copy is `Documents\Worldbuilder\` (world.db + assets/), fixed in `src/main/index.ts` via `APP_NAME` — every mutation writes there instantly (crash safety); dev and packaged builds see the same copy. `adoptLegacyDataDir()` renames the pre-rename `Documents\Dünya` folder on first launch (only when the target does not exist). On top sits a document layer: a **`.world` file** = a SQLite copy with the same schema + an `assets` table (images embedded as BLOBs) + `settings.worldFile` (the file's own path). In `db.ts`: `packWorld` (VACUUM INTO tmp → BLOBs → atomic rename) / `unpackWorld` (close db → copy → open → extract images to a **staging folder** → drop the table → repairs → swap the images in → prune → only then drop the rescue). **The recovery boundary covers `assets/` as well as `world.db`, and it is the LAST line of the function that closes it.** `world.db` has had a rescue copy since the beginning; the images were written straight into `assets/`, so a file that extracted its pictures and then threw was rolled back for the database and not for the folder — the user was told the open had failed and got their world back with someone else's pictures in it, which no backup recovers because backups hold `world.db` alone. Extraction now goes to `assets.incoming/`; the swap moves file by file (NOT a directory rename — a name the new world references but does not carry has always survived an open, and `pruneUnusedAssets` is what decides afterwards) and parks each name it overwrites in `assets.prev/`, so a failure part-way through the swap walks back exactly. `setSetting('worldFile')` and `pruneUnusedAssets()` moved INSIDE that boundary too: both used to run after `rmSync(rescue)`, and either can throw on a hostile file (the upsert needs the primary key our schema declares, and a file writes its own schema; the prune walks a folder the filesystem can refuse). Cost of the swap, measured: 300 images 173 ms, 9999 (the cap) 9 s. Residual, deliberately not closed here: the prune's own deletions are not part of the rollback, so a prune that throws part-way can still have removed files the rolled-back world referenced. Ctrl+S save / Ctrl+Shift+S save-as / open via Ctrl+O or the sidebar buttons (`backupNow` first + confirm when dirty; the renderer reloads after opening). The **dirty flag** lives in main's single IPC dispatch as a method-name regex (`create|update|delete|add|set|restore|retype|import|pick`); the window title is `Worldbuilder — file.world *`; closing while dirty shows a native Save/Don't Save/Cancel dialog (language from `settings.language`). Double-click: `electron-builder.yml` `fileAssociations` (NSIS) + **HKCU is re-registered to the current exe path on every launch** (`reg.exe`, no admin; disabled in dev) — the portable exe stays double-clickable wherever it moves; on startup the `.world` path comes from `process.argv` / the `second-instance` argv. **Start screen:** in the empty view (`view.kind==='empty'`, only with NO open file — `worldInfo().file`) a recent-`.world` list + ＋New world / 📂Open… buttons. The list lives in `userData/recent.json` (`recentWorlds`/`openRecent`/`forgetRecent`, index.ts) — it CANNOT live in `settings`, the working copy resets every launch; `openWorldFile` + `saveWorld` write it, capped at 12, a deleted file stays listed as `missing` (dismissed with ×). `newWorld` follows the launch path (pack to backups → `resetWorld` → reload). The dirty confirm is shared across all three paths (`discardOk`, App.tsx). **A normal (argument-less) launch is ALWAYS a blank document**: a non-empty previous session is packed as a full `.world` into `backups/last-session-<stamp>.world`, then `resetWorld()` (empty schema + empty assets/).

**The session log (`src/main/log.ts` + `src/main/log/`, `src/renderer/src/log.ts`):** every run writes `Documents\Worldbuilder\logs\<date>_<session>_session.log`, opened with a header block (time, session id, version, OS, runtime, memory) and then **one line per meaningful event** — `time · LEVEL · scope.event · key=value…`. It is written for three readers at once: whoever is building the app, whoever is diagnosing a file a user sent, and an LLM being handed that file, which is what fixes the grammar (fixed columns, dotted scopes, values always `key=value`, never wrapped). Errors get a **block** instead, carrying the message, entry point, app context and the **last 50 things the app did** — a stack says where it was standing, the trail says how it got there, and the trail is what usually solves a report. Modules split by one responsibility each: `format.ts` (the grammar, pure — no I/O, so the db self-check can assert it), `sink.ts` (file naming, retention, buffering, the size cap), `ring.ts` (the trail), `logger.ts` (levels, timings, the error report), `thresholds.ts` (**every number in one place** — "slow" is a judgement and belongs somewhere arguable). **`log/` imports no Electron** — `node tests/db.test.ts` exercises it, so `app`-dependent values (version, `getAppMetrics` memory) are passed in; for the same reason its intra-imports carry `.ts` extensions and `Level` is imported as a `type`. Levels are INFO/WARN/ERROR always, **DEBUG behind `prefs.json`'s `debugLog`** (Preferences ▸ Developer, per machine — a shared `.world` must not switch it on for you). Renderer events cross the ONE IPC channel via `logEvents`, **batched 500 ms** (per-event calls would make the log a source of the stutter it exists to find); the `log*` prefix keeps them clear of the dirty-flag regex and `noteCall` skips them. Writes are buffered and flushed on a 1 s timer, **immediately on ERROR** and on `before-quit`. **Nothing may be called per frame** — the one exception is `frame()`, an integer increment on the existing wheel loop, because a permanent `requestAnimationFrame` for an fps counter would undo the on-demand rendering the map is built on. Retention on launch: 200 files and 30 days. Never logged: mouse position, hover, drag coordinates, animation ticks. Never written: world content or file paths — only names, because the file is meant to be pasted into a message.

**Backups + export (the save/export split):** "Save" here is already continuous and automatic (every `updateEntity`/`updateFeature` writes to SQLite instantly) — no manual Ctrl+S needed for the working copy. What was missing was an **Export** (a non-editable, shareable artifact), which exists now: **Backups** (`backupIfNeeded()` in `db.ts`, called once in `app.whenReady` — a dated copy of `world.db` daily into `backups/`; "Back up now" in Settings takes an extra timestamped copy via `api.backupNow()`). **Retention is BOTH age and count** (30 days, 60 files) — age alone bounds nothing here, because a copy is also taken on every launch and every file opened, which reached 297 files and 8.4 GB in three weeks with nothing old enough to prune. **Age means when the BACKUP was taken (`birthtime`), never its mtime:** `copyFileSync` copies the source's timestamps on Windows, so a backup of a world untouched for a month used to be born older than the cutoff and was deleted on the next launch. **`unpackWorld` VACUUMs after dropping the `assets` table** — the drop frees pages without shrinking the file, so the working copy kept the weight of every image it had ever unpacked (measured: 102.4 MB, 26 206 of 26 217 pages free, 40 KB after) and every backup copied it. Restore is deliberately MANUAL — with the app closed, copy a file from `backups/` over `world.db`. **Export** (`exportMap` in `MapView.tsx`): dumps what is currently on screen (mode/year/zoom, base image + polygons/paths/pins) to PNG — via `mainWindow.webContents.capturePage(rect)` (Electron's own capture, no html2canvas); `rect` comes from the renderer's `divRef.getBoundingClientRect()`. UI covering the map (Time strip, zoom HUD, Hierarchy panel, conquest/event hints) temporarily leaves the render via the `exporting` state (two `requestAnimationFrame`s awaited so the DOM updates) — otherwise those controls would end up in the image.

**Notes .txt export (`exportNotes` in `db.ts` + `index.ts` + Settings):** the Settings button dumps every entity's note tabs (`fields['notes']`) into a `Documents\Worldbuilder\notes\<map>\<board>\<folders…>\<entity>\<note>.txt` tree — **the same order the sidebar groups in**, so the folder tree on disk reads like the panel. An entity appears under every map it is drawn on (`entMaps` = entity→map→board ids, from features); mapless → `(no map)`, folderless → `(no folder)`. The `<board>` level appears ONLY for maps that have boards (`settings.mapBoards`), exactly as the sidebar shows no board tier for a boardless map; a missing or orphan board id falls to the first board (MapView's `resolveBoard` rule). One-way (app→.txt), button-triggered; the tree is `rmSync`ed and regenerated each time (renames/deletions come out clean). `safe()` produces Windows-safe names; content uses `\r\n`; the `index.ts` wrapper opens the folder via `shell.openPath`. No schema change. Asserted in the db self-check (map, no-map and board branches).

**What ships beside the exe (the legal set):** five documents, in a `legal/` folder, and the one that is an actual obligation was not the one asked for. electron-builder already places `LICENSE.electron.txt` and `LICENSES.chromium.html` at the install root, covering Electron, Chromium and ffmpeg — nothing covered what is INSIDE `app.asar`, and those two are placed by electron-builder itself with no destination we control, which is why `legal/` holds only the four we author. Leaflet is BSD-2, half a dozen packages are MIT, and the four fonts are **OFL-1.1, which requires its text to travel with the font**. `THIRD-PARTY-NOTICES.txt` is therefore GENERATED (`scripts/gen-notices.mjs`) rather than written: hand-written it would be wrong within a month and **nothing about a stale notice file fails**. It walks the WHOLE tree — the first version listed twelve packages and missed the dozen `@turf` packages leaflet-geoman pulls in, which are bundled into the renderer exactly like anything named in `package.json`. A package with no licence text is a hard exit, with one narrow exception: `@pixi/colord` declares MIT and names its author but ships no file, so the standard text is reconstructed with the holder the package itself names, said plainly in the block. `LICENSE` (MIT, at the repository ROOT where GitHub and npm look for it) is `nsis.license`, i.e. a page the installer will not go past — the one moment a user is guaranteed to be looking. It was `legal/TERMS.txt`, a proprietary document, until the project moved to MIT. What a licence does NOT say — your worlds are your own, back them up, a `.world` from a stranger is someone else’s document — is `legal/NOTICE.txt`, which ships beside the licence rather than in front of it. `PRIVACY.txt` can be short and TRUE because the app makes no network requests at all. `ALPHA-README.txt` is the fourth, added for the first external alpha: install/data-location/recovery/log basics a tester needs and nowhere else says. **The portable ZIP has no installer and therefore no such moment**, which is what `extraFiles` and Help ▸ are for: the whole `legal/` folder sits beside the exe in both distributions (the string form of `extraFiles` for the four whose source path and shipped path are the same, and `{from: LICENSE, to: legal/LICENSE.txt}` for the licence, whose source is the root) and Help opens each file from disk (`openLegal`, a literal from the caller — no path ever crosses IPC; the folder name is joined inside the function, not part of the literal, and `LICENSE.txt` is the one name whose DEV path resolves to the repository root instead of `legal/`). They are kept OUT of the asar (`!legal/**`): one copy, in the folder, findable, because a licence nobody can find has not been given to anyone. Two traps. `.gitattributes` forces LF everywhere and that is WRONG for these five — NSIS renders the licence in a RichEdit control and Notepad opens the others, so they are pinned `eol=crlf` in the working tree at their `legal/` path — and `LICENSE` at the root, for the same reason (stored LF). And **building is not publishing**: electron-builder sees a git tag and decides on its own to publish, failing for a `GH_TOKEN` the release job deliberately keeps out of the environment — `--publish never` lives in the `build:win` script so a local tagged build behaves the same, and the upload stays a separate step with the token scoped to it.
